# Spec: judge sandbox, one-session learning, session summaries

Status: agreed with the user on 2026-10-17 (grilling rounds Q1–Q24). Tickets: `.scratch/judge-sandbox/issues/`.

## Why

Judges must use Apprentice hands-on, and we don't know their Google accounts. Today only `EXPERT_EMAIL` can use the
live workspace, and `/demo` is read-only. A judge also can't record the 8 sessions the full flow needs, so the app must
show learning from **one** short recording. Separately, every session should explain itself in plain language, even
when no pattern has emerged yet.

## Decisions

### Access
- A judge signs in with **any Google account**, then enters the **judge code** once. The server compares it with
  `SANDBOX_CODE` (a server setting, changed by redeploy) and remembers it for that account (Firestore
  `sandboxes/{uid}`). No code set → sandbox off.
- The expert (`EXPERT_EMAIL`) keeps the live workspace exactly as today. An account that is neither expert nor judge
  sees the code screen.
- `/demo` stays public and read-only.

### Workspace
- Each judge gets a **private sandbox** for every workflow: Firestore `workspaces/sandbox-<uid>[-<scenario>]` (AP
  without the suffix, like `live`), recordings `gs://BUCKET/sandbox-<uid>[-<scenario>]/`.
- Workspace becomes a third kind: `Ws = "demo" | "live" | "sandbox"`. Write routes resolve the caller's workspace from
  their account (expert → live, judge → their sandbox), never from the request. Reads accept `?ws=` but a judge can only
  read their own sandbox and the demo.
- The judge plays the expert: answers questions, labels exam cases. Their answers alone shape their graph.

### Starting state
- On first entry (code accepted), each workflow's sandbox gets a **copy of that workflow's sample run** (the demo
  workspace contents).
- Buttons: **Reset to sample** (delete, copy sample again), **Start empty** (delete, leave empty),
  **Delete my sandbox** (delete everything incl. the code redemption).

### Everything the expert can do, within limits
- Per judge, per day-independent totals: **5 recordings, 5 graph builds, 5 exam runs, 5 case generations**.
- Recording: **auto-stops at 5:00** in the browser; the server rejects `duration_s > 330` (5:30 grace) for sandbox
  sessions. No minimum.
- Across all judges: **100 sandbox actions per day** (IST day; an action = any of the four above). Off switch:
  `SANDBOX_ENABLED=0`.
- Limits are enforced on the server and shown on the sandbox start page ("2 of 5 recordings used").

### One-session learning (all workspaces)
- Pattern discovery runs after **any** processed training session; a pattern is the **same departure at least twice,
  in any number of sessions** (replaces `MIN_SESSIONS = 3` and the variants prompt's "2 sessions or 2 times").
- **Quick plan** per workflow: 6 work items, each of the 3 unwritten rules twice, ~3–5 minutes. 2–3 items is fine for
  a first try. Item ids are new and distinct (e.g. `INV-2101..2106`, `SUB-301..306`, `R-401..406`).
  - Invoices: 2 consignment-vendor invoices (approve via statement tab, no PO); 2 urgent critical-vendor invoices
    ₹1–2 lakh after the CFO's line-stoppage email (one approval); 2 renumbered duplicates (reject).
  - Essays: 2 late essays from accommodated students (no deduction); 2 essays with an unquoted copied passage (talk to
    the student); 2 late essays with an extension asked before the deadline (no deduction).
  - Volunteers: 2 sign-ups aged 16–17 with a parent's consent email (accept); 2 returning volunteers on a full shift
    (accept); 2 people with an access need on an upstairs shift (hold, offer ground floor).
- **Sandbox exam**: generated cases only (no held-out recording), **6 cases** covering each rule and each trap,
  labelled by the judge. The live workspace keeps held-out sessions.

### Files for judges
- The sandbox start page offers, per workflow, **downloads only**: the spreadsheet as `.xlsx` with the right tab names
  (Invoices… / Grades, Students / Form responses 1, Shifts, Returning volunteers), the essays (zip of `.docx`), and a
  **Starter emails** `.docx`. Plus the quick-plan item ids and one line: "Upload to Google Drive and open with Google
  Sheets / Docs." Nothing is written to anyone's Drive.
- The packs contain the full synthetic data **plus** the quick-plan items, generated by `make_synthetic` and served as
  static files.

### Sample run
- Now: `scripts/sample_run.py --scenario X` builds a sample run per workflow from text steps on real Gemini (segments
  written from the quick plan, then deviations → questions → canned expert answers → patterns → graph → exam with
  canned labels) into the workflow's **demo** workspace. No video: clip buttons are hidden when a session has no
  recording.
- Later: replaced by the user's real quick-plan recordings (export → seed, as today).

### Privacy and retention
- Consent line before recording in a sandbox: *"Recordings and answers in this sandbox are visible to you and the
  Apprentice organisers, and are deleted after 14 days."*
- **Deletion after 14 days**: a bucket lifecycle rule deletes objects under `sandbox-` prefixes 14 days after upload;
  the app deletes sandboxes whose `created_at` is over 14 days old on startup and on the first request of each IST day.
  No new cloud service.
- **Admin page** (`ADMIN_UIDS` only): list of sandboxes (judge email, created, usage per limit, today's global count)
  and a read-only view of any sandbox (sessions, clips, answers, graph, exam).
- Connect Sheet stays available (optional) in sandboxes; judges see Google's unverified-app warning.

### Session summary (all workspaces)
- After processing, each session gets a **summary**: 3–5 plain sentences plus, per work item, the ordered steps
  followed. New contract model `SessionSummary` (stored as `sessions/{id}/summary/current`), new prompt `summary.md`,
  screened by Model Armor, shown at the top of the session page.

### Observed workflow (all workspaces)
- On every pattern refresh, Apprentice writes the expert's **actual procedure** as numbered steps, each marked "matches
  SOP §x" or "not in the SOP". New model `ObservedWorkflow` (`observed_workflow/current`), new prompt
  `observed_workflow.md`. Always shown on the Patterns page; it is the main content when no patterns exist.
- **Display only**: never an input to the graph builder, the exam case writer or the agents (a leakage test enforces
  it, like `expert_label`).

## Contract changes (announce to Person B; `make types`)
- `Session.workspace`: add `"sandbox"`.
- New: `SessionSummary {session_id, summary, items: [{invoice_id, steps: [str]}], prompt_version, moderation_id}`,
  `ObservedWorkflow {steps: [{n, text, sop_rule | null, in_sop: bool, session_ids}], built_at, prompt_version}`,
  `SandboxInfo {uid, email, created_at, usage: {recordings, graph_builds, exam_runs, case_generations}, limits,
  global_today, global_limit}`.
- `/api/me` adds `role: "expert" | "judge" | "none"`.

## API changes
- `POST /api/sandbox/join {code}` → `SandboxInfo` (copies the sample on first join).
- `GET /api/sandbox` → `SandboxInfo`; `POST /api/sandbox/reset {mode: "sample" | "empty"}`; `DELETE /api/sandbox`.
- `GET /api/sandbox/files/{scenario}/{name}` → the download packs (judges only).
- `GET /api/admin/sandboxes`; admin reads pass `?ws=sandbox&uid=<uid>`.
- `GET /api/sessions/{id}/summary`; `GET /api/observed-workflow`.
- Limit hits return `429 {error: {code: "limit", message: "You've used 5 of 5 recordings in this sandbox."}}`.

## Cloud changes (Cloud_Setup)
- New step: bucket lifecycle rule (delete age 14 days, `matchesPrefix: ["sandbox-"]`).
- Deploy: add `SANDBOX_CODE` (and optional `SANDBOX_ENABLED`) to `--set-env-vars`.
- No new services, roles or secrets.

## Out of scope
- Writing files into judges' Drive; seeding judges' Gmail.
- A judge sandbox for anyone without the code.
- Feeding the observed workflow into the graph or exam.

## Verification
- Backend tests per ticket (seams: auth/workspace resolution, limits, sandbox lifecycle, pattern rule, summary and
  observed-workflow storage + leakage, sweep, admin access).
- Frontend tests: code screen, sandbox start page, limit messages, auto-stop at 5:00, clip buttons hidden without
  video.
- Real-Gemini text dry run per workflow: one quick-plan session yields questions, ≥1 pattern per rule, a graph and an
  exam.
- Deployed: a second Google account joins with the code, records 1 minute, sees questions, rebuilds graph, runs the
  exam; admin page shows it; reset and delete work.
